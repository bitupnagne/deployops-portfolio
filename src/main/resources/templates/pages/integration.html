GL

GitLab

프로젝트, 브랜치, MR, Pipeline 조회와 조작에 사용하는 GitLab 연동 정보입니다.

미확인

등록 여부 확인 중

Deploy System 전용 서비스 계정 토큰을 사용합니다. root/admin PAT는 사용하지 않습니다.

등록 여부 확인 중

GitLab 프로젝트 Webhook(URL: /api/v1/gitlab/webhook, Merge request events)의 Secret token과 동일한 값. 미등록 GitLab 사용자의 MR을 자동 종료할 때 사용합니다.

본인 GitLab 토큰이 없는 사람에게 시스템 공용 토큰을 대신 쓰게 허용할 목록입니다. 최고 관리자는 적지 않아도 항상 허용됩니다. 공용 토큰은 누가 했는지 구분되지 않으므로 꼭 필요한 사람만 적으세요.

NX

Nexus 저장소

Nexus 관리 API와 Docker Registry v2 연결을 확인합니다. 실제 CI push 및 저장소 권한은 파이프라인에서 별도로 검증해야 합니다.

미검사

DeployOps에서 저장소 조회·파일 반입·관리 API에 접근할 주소입니다.

Runner가 접근할 Nexus 기본 주소입니다. /repository/저장소명은 넣지 않습니다. 비우면 관리 API URL을 사용합니다. API·Registry 연결 검사로 Runner 연결까지 확인되지는 않습니다. 변경 후 프로젝트 Maven 설정을 다시 미리보기·적용하고 CI에서 확인하세요.

등록 여부 확인 중

CI와 배포 서버가 사용할 Registry 주소입니다. scheme은 Nexus URL과 같습니다.

DeployOps 컨테이너에서 Registry 검사와 이미지 이력 조회에 사용할 호스트:포트입니다. 비우면 위 주소를 사용합니다.

Nexus 검사 결과는 이 페이지의 현재 입력 기준입니다. 새로고침, 입력 변경 또는 저장 후에는 다시 검사해 주세요. 저장은 연결 검사와 별개입니다.

서버 에이전트

서버 화면에서 에이전트를 등록·승인하고 연결과 실행 준비 상태를 확인하세요.

ART

산출물 전달

빌드 결과물을 배포 대상 서버로 어떻게 넘길지 정합니다. 망분리 구성에서는 반드시 확인해야 합니다.

망분리(개발망·배포망·운영망) 구성이면 밀어 넣기입니다. 직접 받기로 두면 대상 서버가 저장소에 접속하려다 실패합니다.

예: 2g, 1536m. 비우면 위험합니다 — 상한이 없으면 앱이 서버 전체 메모리를 기준으로 동작해, 한 서비스가 노드 전체를 멈출 수 있습니다.

전송한 파일을 잠시 두는 곳. 배포가 끝나면 자동으로 지웁니다.

웹 화면 빌드 결과가 이미지 안 어디에 있는지. 프론트엔드 빌드는 보통 /dist 입니다.
