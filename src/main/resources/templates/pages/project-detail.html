CI/CD 설정

꼭 필요한 것

배포할 때 어느 이미지를 내려받을지 정합니다. 비어 있으면 배포가 시작되자마자 멈춥니다.

HTTP가 없는 PROC는 컨테이너 실행 상태를 선택합니다. 없음은 TEST에서만 허용하며 기동 실패를 판정하지 않습니다.

서버그룹의 외부 VIP와 조합할 프로젝트 기본 포트입니다. 실제 WAS 헬스체크·컨테이너 공개 포트와 별개이며 환경·그룹마다 동일한 서비스 VIP 포트를 사용합니다. L4 포트 매핑은 운영자가 설정하세요. WEB 단위·공개 포트 없이 CONTAINER_RUNNING으로 확인하고 기본 네트워크·bridge·none을 사용하는 PROC는 VIP 포트를 비워두면 공유 그룹의 VIP를 사용하지 않습니다. host 또는 사용자 정의 네트워크는 외부 접속 가능 여부를 추측하지 않습니다.

빌드 설정 비워 두면 CI 파일에 적힌 대로 빌드합니다

Dockerfile과 GitLab CI에 함께 적용하는 모드입니다. 기존 파일을 우선 사용하거나 소스 구조를 감지해 설정을 제안합니다.

단일 C 파일의 경로입니다. 예: src/main.c

폐쇄망에서는 Nexus에 반입한 베이스 이미지명을 사용합니다.

이미지 빌드 · 저장소 세부 Dockerfile 위치와 Nexus 저장소 이름을 바꿀 때만 씁니다

비워 두면 서버에 설치된 기본 에이전트 스크립트를 씁니다.

컨테이너 실행 설정 이 프로젝트의 기본 네트워크·환경파일·실행 계정

대상 서버에 있는 네트워크 이름입니다. 비우면 Docker 기본 네트워크를 사용합니다.

각 대상 서버에 미리 준비된 파일의 절대경로입니다. 비우면 환경파일을 주입하지 않습니다.

호스트:컨테이너 포트를 쉼표로 구분합니다. 호스트 포트는 중복할 수 없습니다. 비우면 HTTP 헬스체크를 사용하는 경우에만 헬스체크 포트 하나를 같은 번호로 게시합니다. 컨테이너 실행 상태만 확인하는 경우에는 포트를 게시하지 않습니다. HTTP 헬스체크는 지정한 호스트 포트에서 계속 수행합니다.

UID 또는 UID:GID입니다. 비우면 이미지의 기본 계정을 사용합니다. 배포 단위의 계정이 있으면 그 값을 우선합니다.

필요한 항목만 쉼표로 구분합니다. 비우면 추가하지 않습니다. 배포 단위에 지정된 값이 있으면 그 값을 우선합니다.

프로젝트 기본 컨테이너에 적용합니다. 배포 단위가 있으면 해당 단위의 실행 설정을 사용합니다.

저장소 Dockerfile · GitLab CI

조회한 원문을 편집하거나 소스 유형별 초안을 확인한 뒤 MR로 제안합니다. 승인·병합 전에는 대상 브랜치의 파일이 바뀌지 않습니다.

Dockerfile은 저장된 프로젝트·활성 배포 단위의 경로로 조회합니다. 프록시 재적용 단위는 Dockerfile을 사용하지 않습니다. GitLab CI 파일은 프로젝트 전체에 공통으로 적용됩니다.

소스 유형이 확인되지 않으면 직접 선택하세요. 감지는 기존 파일·편집 내용·프로젝트 설정을 자동으로 바꾸지 않습니다.

배포 단위 추가

        
      

      

        
        
프로젝트마다 WEB·WAS 역할별로 활성 배포 단위를 하나씩 사용합니다. PROC와 PROC 관리자는 각각 별도 프로젝트로 등록해 배포합니다.

        

          

            
            
          

          

            
            
          

          

            
            
          

          

            
            
          

          

            
            

              
              
            

            
활성 단위마다 서로 다른 저장소를 사용합니다. 그중 한 단위의 저장소는 프로젝트 대표 이미지 저장소와 같아야 합니다.

          

          

            
            
          

          

            소스 빌드 설정
            
MR 승인·병합 후 CI가 단위별 이미지를 만들고 다이제스트를 확정합니다. 빈 값은 프로젝트 설정을 상속합니다. WEB 정적 파일은 별도 빌드 명령과 산출물 경로를 지정하고, 두 단위의 산출물 디렉터리가 겹치지 않게 하세요. 프록시 재적용은 이미지를 빌드하지 않습니다.

            
            
            
            
            
            
            
            
            
            
            
경로는 Git 저장소 루트 기준 상대 경로입니다. 절대 경로·상위 경로(..)는 사용할 수 없습니다. 변경 후 프로젝트 CI/CD 화면에서 설정을 다시 생성하고 MR로 반영하세요.

          

          

            
            
            
웹/API는 로컬 HTTP 응답을, HTTP가 없는 PROC는 컨테이너 실행 상태를 확인합니다. PROD에는 헬스체크 설정이 필요합니다.

          

          

            
            
          

          

            
            
            

              
              
              
              
              
              
              
환경별 값을 비우면 공통 Host를 사용하고, 공통 값도 비우면 기존 기본 호스트를 검사합니다. WEB 프록시 전용입니다. nginx의 server_name에 맞는 호스트 이름을 입력하세요. 연결은 해당 서버 내부에서 수행하며, 비워 두면 기존 기본 호스트를 검사합니다. 포트·경로는 위 항목에서 설정하세요.

            

            
            
            
컨테이너 프로세스의 숫자 사용자·그룹 ID입니다. 포트 매핑을 입력하는 칸이 아닙니다. 비우면 프로젝트 실행 계정, 그 값도 없으면 이미지의 USER를 사용합니다. 저장소 연결에는 root가 아닌 UID:GID를 명시하고, 해당 계정에 실제 마운트 경로의 읽기·쓰기 권한을 준비하세요. 게시 포트는 프로젝트의 CI/CD 설정에서 지정합니다.
